# 自查机制（Self-Check Protocol）

> 核心原则：用户指出一个问题 = 可能存在N个同类问题。不要只修一个，要扫描全部。

---

## 触发条件

当用户指出报告/数据/代码中的任何问题时，立即启动以下流程。

---

## 四步自查流程

### 第一步：定位问题类型

判断用户指出的问题属于哪一类：

| 类型 | 示例 | 扫描范围 |
|------|------|----------|
| **数据一致性** | 96跑了2个参数，2031只跑了1个 | 所有策略的96 vs 2031参数变体数量 |
| **格式一致性** | 某个表格缺了参数列 | 所有同类表格是否都缺 |
| **内容完整性** | 某个策略详解缺了入场条件 | 所有策略详解是否都缺 |
| **逻辑一致性** | IS和OOS的数据来源不同 | 所有对比数据是否同源 |
| **标注一致性** | 某处用了缩写没解释 | 全文扫描未解释的缩写 |

### 第二步：扫描所有同类项

用以下检查清单逐项核实：

- [ ] **参数变体对称性**：96和2031是否跑了相同的参数组合？每个策略有几个变体？是否两边一致？
- [ ] **表格结构对称性**：同类表格的列是否完全一致？是否有某个表格多了/少了列？
- [ ] **策略覆盖完整性**：已测策略是否在每个出现的表格中都有数据？有没有遗漏？
- [ ] **数据源一致性**：所有回测数据是否来自同一次运行？有没有混用不同版本的数据？
- [ ] **结论一致性**：分类总览表的结论 vs 详解段的结论 vs 最终推荐的结论，三处是否一致？

### 第三步：列出所有发现的问题

格式：
```
用户指出的问题：[原始问题]
自查发现的同类问题：
1. [问题1] — [影响位置]
2. [问题2] — [影响位置]
3. ...
```

### 第四步：一并修正

- 向用户报告自查发现
- 一次性修正所有同类问题
- 不要分批修补，避免反复打扰用户

## 常见自查场景

### 场景1：参数变体对比
- **检查点**：每个策略在96和2031上是否测试了相同的参数变体
- **常见问题**：96只跑了最优参数，2031跑了多个；或反过来
- **修正方法**：补跑缺失的参数组合

### 场景2：表格列对齐
- **检查点**：所有分类总览表（一~七）的列结构是否完全一致
- **常见问题**：某些表加了新列，其他表忘了加
- **修正方法**：统一修改所有同类表

### 场景3：策略状态同步
- **检查点**：同一策略在不同位置的"已测?"状态是否一致
- **常见问题**：总览表标记✅，但详解段数据是旧的
- **修正方法**：以最新回测结果为准，同步更新所有位置

### 场景4：IS/OOS数据配对
- **检查点**：每个IS数据是否都有对应的OOS数据？参数是否一致？
- **常见问题**：IS用了一组参数，OOS用了另一组
- **修正方法**：确保IS和OOS使用完全相同的参数
